## GOAL
A cheap AliExpress USB/HDMI "microscope" (SigmaStar Mercury6 dashcam board + Sony IMX307) turned into a hackable cinema camera with our own firmware app `camapp` replacing the vendor `cardv`. "Unmatched control": every value a real sensor/ISP/encoder parameter, free numbers, not presets. Reliability matters (real film use).

## HARDWARE / ACCESS

- UART `/dev/ttyUSB0` 115200 (one program at a time). Scratchpad helpers: `sh.py "" "cmd"` (output often late: re-read with `sh.py "" "" "cmd"`), `brio.sh NAME` (BRIO webcam photo of the HDMI monitor; fails with "no frame" while the Windows Camera app holds the BRIO), `hset.sh HMAX`, `cpustat.sh` (push to /tmp after a reboot), `hsweep445.sh`.
- USB: own configfs UVC gadget (see UVC). HDMI 1080p60 to the user's LG (a 1080p 100 Hz monitor). OSD framebuffer `/dev/fb0` 1600x900 ARGB8888 scaled to 1080p, colour key 0x0a0a0a.
- SD vfat at `/app/bin/sd` (58.4 GB card, ~14 MB/s writes).
- Inputs: `/dev/input/event0` body buttons (UP 103, AE 105, MENU 139, OK 28, DOWN 108); `/dev/input/event1` IR remote. **Remote has no OK button and no long press**: play/pause = confirm ("Press OK" rows) or reset (value rows), mirror button (sends "loupe") = back in the menu, MENU closes the menu (reopens where it was).

## BOOT CHAIN
`/bootconfig/demo.sh` loads modules, runs the vendor `/customer/gadget/udc-uvc.sh` (loads libcomposite, usb_f_uvc, configfs at `/customer/config`, then `g_webcam`), then `cardv`. Our `/config/cardv` wrapper: if `/customer/camapp/enable` exists, count `boot_attempts` and exec `/customer/camapp/boot.sh` (3 bad boots -> stock cardv). `boot.sh`: kill vif.sh, mount SD (retry), run `uvc-gadget.sh` (replaces g_webcam, falls back to it), start camapp (`/tmp/camapp.log`), reset the counter after 30 s healthy. Sources in `tools/device/flash/`. Escape: UART Ctrl+C, `rm /customer/camapp/enable`, SOP8 clip.

## KEY FINDINGS (still true)
- imx307 driver: `pCus_SetFPS` only 3-30 fps (driver units), VMAX never below 1125; `AEStatusNotify` rewrites VMAX/SHS1 every AE update; HMAX/window registers are only written at init; `pCus_SetOrien` only marks orientation dirty and a frame callback later writes 0x3007 with the orientation bits alone (clears WINMODE) - crop mode writes 0x3007 itself. `pCus_SetAEUSecs` computes us x 1000 in 32 bits: wraps above 2.147 s real at <=60p.
- Speed: fps = 148.5e6 / (HMAX x 1125). Clean needs line time >= MIPI data time + ~1 us: HMAX_min ~ (W+28) x 5/6 + 160 (full width 1760 = 75p verified; 1280 wide 1250 = 105.6p, 1200 corrupts left columns). 891 Mbps MIPI settings garble (SoC RX) - full-width 120p parked. `driver_time_scale()` = 4400 / HMAX.
- Crop: sensor window (WINMODE 0x40, WINPH, WINWH = X_OUT = W+28) at start; VIF crop goes in the DEV attr (port rect with a y offset is refused); ISP SetInputPortCrop; SCL scales every port to 1920x1080. Vertical crop gives no speed (driver VMAX floor).
- VENC: rate control word [10] (H.265 CBR 8 / VBR 9, H.264 CBR 1 / VBR 2); VUI Get/Set only valid after StartRecvPic; H.264 time_scale counts fields (2 x fps x 1001). JPEG quality = word 0 of JpegParam. Bind frame-rate args are 16-bit fps (no timelapse gating).
- OSD: draw areas that get cleared (status, corners, menu) off-screen and copy changed rows (else flicker); analysis cells run under the status text (composited), cleared elements invalidate cells under them.
- UVC: vendor g_webcam advertised fake sizes + a still pin (Windows Camera timed out); own gadget fixes it; soft_connect toggle at start survives camapp restarts; frames paced to the host interval (was 120/s: 27% of a core in USB work).
- Resources (100p crop, scopes + UVC on): CPU ~60% of 2 cores; waveform+histogram ~30% of a core; ISP kernel threads ~40%.
- ISP/3A struct offsets (AE info avgY/target/LV, metering weights, NR3D, WDR, CCM, gamma, histogram, HSV, noise) are recorded in the handoff(5).md technical log and in the code comments (isp.c, camapp.c).
- RAW/DNG (2026-09-29): VIF output is FBC-compressed to 8 bpp unless mi_vif.ko param g_bFBCMode=N (camapp sets it before the pipeline; picture fine). Uncompressed RG_10BPP = little-endian 10-bit bit stream, stride W*10/8. Raw buffer = readout rotated 180 deg vs the picture (mirror/flip 0) -> DNG Orientation 3, RGGB at (0,0), black 60 (reg 0x300A), white 1023, ColorMatrix1 from ISP CCM + AWB gains. dng.c; FIFO `dng [x y w h]`, `photoraw 0|1`; photo writes IMG_nnnn.DNG next to the JPEG. Verified: red packet region renders red after WB; full DNG 4147680 bytes, frames keep flowing. Verified 2026-09-29 by `dngview` (raw developed on the device to a 160x90 PPM with the DNG black/WB/matrix/orientation): orientation and colours match the live picture. Unverified: mirror/flip on, crop mode, opening in Lightroom/Resolve (user).
- SD bus: 50 MHz 4-bit SD high-speed (~25 MB/s ceiling); UHS 1.8 V switch fails on this board ("Single Volt doesn't ready"). Measured 9.5 MB/s write, 18.7 MB/s read.
- Playback (parked): camera decoder smears the bottom of 1080-high H.265; a killed decoder breaks VDEC until camapp restarts.
